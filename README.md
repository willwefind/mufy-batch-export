# Mufy 批量导出

把 mufy 上**所有角色的聊天记录**一次性导出来，存成能长期保存、能当小说翻的文件。

mufy 自带的导出只能在存档列表里一条一条点。角色多、存档多的时候基本没法用。

> ⚠️ 非官方工具，和 mufy 官方无关。它走的是网页自己在用的接口，官方改接口就可能失效。
> 只读你自己的账号数据。
>
> 🔞 **面向成年用户。请勿向未成年人传播本工具或站点地址。**

---

## 先读这一段，能省你很多时间

**这个仓库里没有「App」。** 点开 `make-epub.py` 或 `mufy-batch-export.user.js` 会看到一屏
代码——**那是正常的**，它们是「代码文件」，不是应用程序，点开只会看到文字。

要用它们，得让**浏览器**去跑（下面第一步会教）。

| 你想做什么 | 需要什么 | 能在手机上做吗 |
|---|---|---|
| **导出聊天记录** | 浏览器 + 一个能跑脚本的扩展 | ✅ 可以（见[手机教程](#附手机上全程走完iphone-实测)） |
| **转成电子书（EPUB）** | 同上，**v1.10 起不用装 Python 了** | ✅ 可以 |
| **在电脑上翻看（网页阅读器）** | 电脑 + 浏览器 | ❌ 不行（手机选不了文件夹） |
| **在手机上读电子书** | 微信读书 / 图书 / 静读天下 | ✅ 可以 |

**一句话：想在电脑上做，照下面的正文走；只有手机，跳到最后那节手机教程。**

## 第一步：导出你的聊天记录（电脑上）

### 1. 装一个浏览器插件

用电脑打开 Chrome 或 Edge，安装 **Tampermonkey（篡改猴）**：

<https://www.tampermonkey.net/>

点进去选你的浏览器，按提示装上。装完浏览器右上角会多一个灰黑色的图标。

### 2. 装脚本

点这个链接：

<https://raw.githubusercontent.com/willwefind/mufy-batch-export/main/mufy-batch-export.user.js>

Tampermonkey 会自动弹出一个安装页面，点 **安装** 就好。

> 如果没弹安装页、只看到一屏代码，说明 Tampermonkey 没装好或没启用。
> 那就手动来：点浏览器右上角的 Tampermonkey 图标 →「添加新脚本」→
> 把那一屏代码**全选复制**粘进去 → 按 `Ctrl+S` 保存。

### 3. 开始导出

1. 打开 mufy，登录，随便进一个角色的聊天页
2. 页面**左下角**会出现一个 **「⬇ 批量导出」** 按钮，点它
3. 面板里选：
   - **范围** → 想备份全部就选「全部聊过的角色」
   - **输出方式** → 想留原始备份就用默认的「每段对话一个文件（打包成 ZIP）」；
     只想拿来当小说读，直接选「**每个角色一本电子书（EPUB）**」，一步到位
4. 点 **开始导出**，然后等着

导出好的文件会自动下载到你浏览器的下载文件夹里，每个角色一个 `.zip`（或一本 `.epub`）。

> **两种输出选哪个？** 想两个都要就跑两遍，互不影响。
>
> - **ZIP**：完整备份。含 `_原始数据.json`（一字不改的原文）、每段对话一个 md、开场白、目录。
> - **EPUB**：成品电子书，直接导进微信读书 / 图书就能翻。正文是清理过的（去掉
>   `<think>`、状态栏 HTML、给模型看的规则行），**不含原始数据**。

> **跑之前记得做这两件事，不然会白跑：**
>
> 1. 浏览器设置里把「**下载前询问每个文件的保存位置**」**关掉**
>    （地址栏输 `chrome://settings/downloads`）。不关的话，每个角色都会弹一次
>    「另存为」窗口，几百个角色就是几百个窗口。
> 2. **跑的时候别把这个标签页切到后台。** 浏览器会给后台标签页降速，导出会卡住。
>
> 中途浏览器会问一次「是否允许下载多个文件」，点**允许**。

## 第二步之 A：在电脑上翻看

打开这个网页，点「选择存档文件夹」，选中放那些 zip 的文件夹：

### 👉 <https://willwefind.github.io/mufy-batch-export/mufy-reader.html>

不用解压，它直接读 zip。左边是角色和章节，右边是正文。

- 字号、行距、页宽、字体、日夜底色都能调，设置会记住
- 键盘 `←` `→` 翻章
- **隐藏我的发言**：RP 记录里你发的常常是 `$指令`，藏起来只剩角色的叙述，最像读小说
- **只导入一次**：第一次选完文件夹后它会记住内容，以后打开直接就是完整书架

> **你的存档不会上传到任何地方。** 这是个纯前端网页，文件全程只在你自己电脑上读。
>
> ⚠️ **别选云盘目录**（WPS 云盘 / OneDrive）。云盘里的文件是「占位文件」，
> 本地只有壳，浏览器读不到，会显示「一个 zip 都没有」。
> **先把文件夹复制到本地硬盘**（比如 D 盘），再选那个副本。

## 导出的东西长什么样

每个角色一个 zip，解开来是这样：

```
00_开场白.md                                   ← 角色卡自带的开场白
00_目录.md                                     ← 索引，可点进每一篇
01_20260806-2352_闷热湿黏的梅雨夜 · 宴会厅.md
02_20260531-0237_我给这段存档写的备注.md          ← 你写过备注的，用你的备注
03_20260531-0101_未存档_沉闷微雨的夏夜.md        ← 你没按过保存的那段
_原始数据.json                                  ← 完整原文备份
```

文件名是 `序号_日期_线索`。你写过备注的用备注；没写的自动取那段开场白的场景抬头。
每个文件的修改时间也是对应日期，资源管理器里能按时间排。

## ⚠️ 最重要的一件事：你现有的备份可能是缺的

如果你已经用别的办法导过 mufy，**很可能少了两样东西**。

mufy 的「存档」是你按了「保存并开启新对话」才产生的。只顺着存档列表导，会漏掉：

**一、你聊过但从没按保存的对话。**
实测在一个 200 多角色的账号上：102 个角色一条存档都没有，
但里面躺着 **1356 条消息**（最长的一个 112 条）。而且有存档的角色也照样漏——
抽查 25 个，其中 24 个的最后一段没进过存档，又是 706 条。

**二、角色卡自带的开场白。**
它不在对话记录里，是挂在角色卡上的独立字段，实测一个角色的开场白有 1400 多字。
每个角色都有，一个都跑不掉。

这两样这个工具都会导出来（没存档的那段文件名带 `未存档_`，开场白是 `00_开场白.md`）。
**我前两版都漏了，跑完还以为导全了。**

> 顺带一提：脚本能捞的是「最后聊的那段」。一个角色如果有**好几段**都没存过档，
> 更早的那些谁也够不着。**真正想留住的对话，还是在 mufy 里按一下
> 「保存并开启新对话」最稳。**

## 常见问题

**Q：那个「⬇ 批量导出」悬浮按钮挡住了 mufy 的按键，怎么办？**
更新到 **v1.9**。手机／窄屏下按钮会自动抬到底部导航上方，不再压住首页键。
按钮右上角有个 **✕**，点一下当次收起（刷新页面就回来）。

**Q：怎么彻底关掉这个脚本？**
点浏览器右上角的 **Tampermonkey 图标**，把「Mufy 批量导出聊天记录」的开关关掉就行。
想再用的时候打开开关、刷新页面。
（如果你是用控制台粘贴的方式装的，关掉标签页就没了。）

**Q：我有一段对话上万轮，这工具扛得住吗？**
扛得住。合成了一段 **1 万轮 / 2 万条消息** 的对话做过全链路实测：
导出 40 次请求全部抓到、0 重复 0 遗漏；转成的 EPUB 导进微信读书能正常打开和跳目录；
用网页阅读器打开那一章也不卡。**不需要你做任何特殊处理。**

**Q：手机上点 `make-epub.py` / `mufy-reader.html` 只看到一堆代码？**
正常，它们是代码文件不是 App。`make-epub.py` 要电脑上的 Python；网页阅读器要选文件夹，
手机做不到。**但导出和转电子书现在手机上能做了**，见下面的手机教程。

**Q：手机上能全程走完吗？**
能。**iPhone（Safari + Userscripts 扩展）已实测走通全程**：装脚本 → 导出 → 出 EPUB →
微信读书打开。安卓也有人用 **Via 浏览器**自带的脚本功能跑通过。见最后一节。
> 只有「网页阅读器」还是电脑专用（它要你选一整个文件夹，那是桌面浏览器才有的能力）。
> 手机上读就读 EPUB，本来也更像读书。

**Q：点仓库里的 html 链接为什么显示的是代码？**
GitHub 的 raw 地址会把网页文件当纯文本发，电脑手机都一样。
要用阅读器请点上面那个 **github.io** 的地址；想下载文件就点文件页右上角的
**Download raw file**。

**Q：导出跑到一半，文件却一个都没出现？**
八成是「下载前询问每个文件的保存位置」没关，或者「允许下载多个文件」没点允许。

**Q：阅读器说「一个 zip 都没有」？**
你多半选了云盘目录。先把文件夹复制到本地硬盘再选。

**Q：提示「续不上登录态」？**
mufy 的登录凭证只活 15 分钟。脚本会自动续，真提示这句就是掉登录了，
刷新 mufy 页面（必要时重新登录）再来。

**Q：跑到一半报错停了？**
脚本对单个角色的失败是容错的，会跳过继续跑，最后会报「成功几个、失败几个」。
个别失败可以用「手动填角色 ID」单独补。

**Q：导出的长对话好像少了内容？**
先看那一篇 md 的开头有没有一行红字「🔴 这一段没导完整」，以及导出结束时有没有
「🔴 有 N 段没导完整」。有的话就是抓取途中网络抖了，**把那个角色单独重导一次**通常就好。

没有红字的话，条数就是接口给的全部。你可以自己核对：
`_原始数据.json` 里每段都有 `expectedCount`（接口说共多少条）和 `messageCount`（实际拿到多少），
两个数一样就是完整的。

> v1.8 之前有个坑：长对话翻页翻到一半失败时，**已经抓到的几百条会被整个丢掉**，
> 退回成存档里的一问一答（2 条），而且只在角落留一个小小的 ⚠️。
> 现在改成抓到多少留多少、并在文件开头和结尾都明确报出来。
> **长对话才需要翻页，所以这个坑专挑长记录下手** —— 如果你之前用旧版导过，值得重导一次。

## 附：手机上全程走完（iPhone 实测）

只有手机、没有电脑也能用。**v1.10 起电子书直接在浏览器里生成，不再需要 Python，
所以整条链路手机上就能闭环**：装脚本 → 导出 → 出 EPUB → 读。

> ✅ **iPhone（Safari + Userscripts）已实测走通全程。**
> 安卓那边有人用 **Via 浏览器**自带的脚本功能跑通过（Via / X 浏览器 / Kiwi 都自带这类功能）。

### iPhone / iPad

**1. 装 Userscripts**（App Store 搜，免费开源）。iOS 上没有 Tampermonkey，那个只有 Mac 版。

打开它一次，它会让你**指定一个存脚本的文件夹**——在「文件」App 里新建一个就行。

**2. 打开扩展**：设置 → Safari → 扩展 → **Userscripts** 打开，网站权限给「允许」
（选「始终允许」省事，不然每次都要点一下）。

**3. 把脚本放进去**：Safari 打开下面这个地址，全选复制——

<https://raw.githubusercontent.com/willwefind/mufy-batch-export/main/mufy-batch-export.user.js>

然后点地址栏左边的 **ᴀA / 拼图图标 → Userscripts → 新建脚本**，粘贴进去保存。

**4. 导出**：Safari 打开 mufy 登录 → 随便进一个角色的聊天页 → 左下角出现
**「⬇ 批量导出」** → 范围选「当前角色」、输出方式选「**每个角色一本电子书（EPUB）**」→ 开始。

**5. 读**：Safari 右上角的下载箭头（或「文件」App → 下载）里就是那本 `.epub`，
点开 →「用其他应用打开」→ 微信读书 / 图书 / 静读天下。

### 手机上的几条注意

- **先只导一个角色试**，确认整条路通了再说。
- **手机上建议选 EPUB，别选 ZIP**：几百个 zip 灌进手机下载目录很难管，而且在手机上也没法用
  网页阅读器打开（那个要选文件夹，桌面浏览器才行）。
- ⚠️ **一次导几百个角色，手机上没实测过**（实测的是单个角色）。要整体备份，
  能用电脑就用电脑；只有手机的话建议分批导，别一次点全部。
- ⚠️ **跑的时候别切到别的 App**。手机浏览器会把后台页面暂停甚至直接回收，导出会断。
  屏幕别锁，导完再走。

### 面板选项

| 选项 | 说明 |
|---|---|
| **当前角色（本页）** | 只导你正在看的这个角色 |
| **全部聊过的角色** | 想整体备份就选这个 |
| **全部已关注角色** | 你点过关注的全部角色，**包含从没聊过的**（会自动跳过并报数） |
| **手动填角色 ID** | 从地址栏 `roleId=` 后面那串复制过来 |
| **每段对话一个文件（ZIP）** | 默认。N 段对话 = N 个 md，打包成一个 zip |
| **全部合并成一份 Markdown** | 想一口气通读时用 |
| **每个角色一本电子书（EPUB）** | 直接出成品书，不用装 Python。一段对话一章，开场白单独一章，自带封面 |
| **清理 think / 状态栏 HTML** | 只影响 Markdown 可读性；JSON 永远是完整原文。**EPUB 一律清理**（书是拿来读的） |
| **附带 JSON 完整备份** | 建议勾着，这才是真正的备份 |

### 「关注」和「聊过」不是同一批人

`isFollowed=true` 返回的是**你关注的全部角色**，包括从没聊过的，而不是两者的交集；
反过来也有你聊过却没点关注的。想整体备份，选「全部聊过的角色」。

实测某账号：关注 291 个，其中真的聊过 192 个，从没聊过 99 个，另有 20 个聊过但没关注。

### 它是怎么工作的

三个接口，都带 `Authorization: Bearer <localStorage['mufy-token']>`：

| 接口 | 作用 |
|---|---|
| `GET /api/characters/query_session` | 角色列表（含 `lastSessionId`） |
| `GET /api/sessions/query_archives?characterId=` | 某角色的存档列表 |
| `GET /api/dialogs/query?sessionId=&characterId=` | 某段对话的全部消息 |
| `GET /api/characters/get?id=` | 角色名和 **开场白（`greeting`）** |

流程：取角色列表 → 每个角色取存档 → 按 `sourceSessionId` 去重、再补上 `lastSessionId`
→ 逐段抓全文 → 加上开场白 → 渲染 Markdown → 打包 ZIP → 浏览器下载。

ZIP 是脚本按格式自己拼的，压缩用浏览器原生的 `CompressionStream`，**不引任何外部库**。

EPUB 说到底就是一个结构固定的 ZIP，所以 v1.10 把整套生成逻辑搬进了浏览器——
封面用 canvas 画（不带任何字体文件，用系统自带的宋体），从此不需要 Python。
`make-epub.py` 仍然保留，给「已经导过一堆 zip、不想重导」的人用。

**两条路出的书是等价的**，这不是估计：在一个 200 多角色的真实账号上，
两边各出了 211 本，逐项比对书 ID、章节清单、目录标题、以及每一章的正文全文，
**211 本全部逐字节一致**。合规性用官方 epubcheck 5.1.0 校验：**0 errors / 0 warnings**。

> 移植时逮到过一个真差异：JS 的 `slice` 按 UTF-16 码元算，Python 的 `[:n]` 按字符算，
> 标题里只要出现 emoji 或花体字（一个字占两个码元），两边就会截出不同长度。
> 211 个里咬中 3 个。改成按码点截之后归零。

请求之间留了 120–300ms 间隔，遇到限流会退避重试——**别改激进，那是别人的服务器。**

### 超长记录：实测数字

有人担心长对话会被吞。这里是**合成一段 1 万轮（2 万条消息）的对话**推过整条链路的实测结果：

| 环节 | 结果 |
|---|---|
| 翻页抓取 | 40 次请求，2 万条**全到，0 重复 0 遗漏** |
| 渲染 Markdown | 98 ms，单篇 24.5 MB |
| 打包 ZIP | 448 ms，堆内存 33 → 50 MB |
| 转 EPUB | 成书，单章 XHTML 21 MB |
| **EPUB 在微信读书** | 真机导入，**打开正常、跳目录正常** |
| **网页阅读器** | 2 万条一次性进 DOM（约六万个元素），**不卡** |

结论：**不需要按章切分，也不需要分页渲染。** 一万轮以内不用做任何特殊处理。

另外实测：`/api/dialogs/query` 的 `pageSize` 不限于 100（试到 2000 都接受），
而且 100 / 200 / 500 三种页大小翻出来的唯一 `dialogsId` 集合**完全一致、0 重复 0 漏掉**——
偏移量是准的。所以 v1.9 起默认每页 500，一万轮对话的请求数从 200 降到 40，
**暴露在网络抖动下的机会少 5 倍**。

真实性说明：合成文本是同一句重复，所以压缩率高得不真实（21 MB 的章压成 96 KB）。
但压力点是**解压后**那 21 MB 的解析与渲染，那部分是真的。

### 关于安全

脚本读你浏览器里的 mufy 登录凭证，这是它能工作的前提。
它**只把这个凭证发给 mufy 自己的接口**，不外传、不上报、不统计、不引第三方库。

但你不该因为我这么说就信。源码在这儿摊着，三万字节，能读的自己读一遍，
读不动的可以整段丢给任何一个 AI 让它讲给你听。
**「作者说它安全」从来不是安全的理由，「你能自己查」才是。**

往浏览器控制台粘代码本身有风险，浏览器弹的那句「不要粘贴不明代码」是对的。
装 Tampermonkey 至少代码留在本地、随时可查。
